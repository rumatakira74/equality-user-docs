## Что переводится и куда

Переводятся все русскоязычные .md user-docs на ТРИ языка: испанский (es), португальский (pt), китайский (zh). Переводы кладутся в три каталога в корне репо с зеркальной структурой (оригиналы не менять):

- docs/01-about.md, docs/02-getting-started.md, docs/03-operations.md, docs/04-security.md, docs/05-faq-glossary.md, README.md, DISCLAIMER.md →
  - es-translation/docs/<то же имя>, es-translation/README.md, es-translation/DISCLAIMER.md, плюс es-translation/GLOSSARY-ES.md;
  - pt-translation/ — зеркально, плюс pt-translation/GLOSSARY-PT.md;
  - zh-translation/ — зеркально, плюс zh-translation/GLOSSARY-ZH.md.

Не переводятся: LICENSE (юридический текст, главенствует русский оригинал), служебные отчёты (REPORT-*.md, FINDING-*), prompts/, eng-translation/ (чужая тема), файлы других репо.

## Правила перевода

- Варианты языков — строго по локализации приложения (app/lib/l10n): сверить суффиксы локалей и взять те же варианты (например es-419/es, pt-BR/pt, zh-Hans/zh); если в приложении вариант не выражен — нейтральный испанский, бразильский португальский, упрощённый китайский.
- Тон: простой язык конечного пользователя, обращение на «you»/«usted» по нормам языка, без канцелярита; для zh — понятный технико-бытовой стиль без литературных вольностей.
- Термины платформы — строго по существующим текстам: сначала локализация приложения (es/pt/zh), затем английский канон (KNOWLEDGE-ENG, README-ENG: vouching, guardians, slots, demurrage, seigniorage, attestation, Eq-<hash8> и т.п.) — сверять, не изобретать. Если термин в локализации приложения отсутствует, в es/pt оставить английский термин (общепринятая практика), в zh — китайский перевод с английским термином в скобках при первом упоминании. Имена полей, флагов, команд, пути, метки (protocolVersion, v9.16, Eq-, K=3, PIN) не переводятся.
- Глоссарий RU→ES/PT/ZH зафиксировать в GLOSSARY-*.md ДО начала перевода соответствующего языка и применять единообразно.
- Markdown-структура сохраняется 1:1: уровни заголовков (якоря), списки, таблицы, блоки кода, цитаты-предупреждения.
- Внутренние относительные ссылки в переводах ведут на переведённые файлы (структура зеркальная — относительные пути сохраняются); внешние ссылки и ссылки на GitHub не менять.
- Числа, версии, размеры окон (48 ч, 14 дней), пороги, проценты — без изменений; сверка фактов перевода с оригиналом обязательна.
- Спорные термины и условные места — списком в FINDING-L10N-NOTES.txt (в корне ветки рядом с каталогами переводов), работу не блокировать.

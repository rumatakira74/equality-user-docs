# 1. 关于平台

## 它是什么

Equality Project 是一个平台：社区（学校、合作社、志愿小组、侨民、基金会、活动组织者）在其中**在成员的手机上**启动**自己的孤立网络**：

- **没有服务器**——网络就活在手机上；
- **没有管理员**——没有人能「关掉」网络或更改它的规则；
- **没有运营成本**——不需要为托管和维护付费。

每张网络给成员三样东西：

1. **一个人 ≈ 一个钱包。** 只能通过在任成员的担保，加上手机的硬件验证才能进入。这是对付虚假账号的主要屏障。
2. **平等的周期性权利。** 网络的「单位」（小时、配额、积分）按时间表**平均**发行给所有活跃成员。
3. **公开可验证的历史。** 成员的声誉——钱包账龄、谁为谁担保过、贡献——对网络所有成员可见。

什么算「单位」以及能用它做什么，由**网络配置（profile）**决定：内部货币、时间银行、共享资源的配额、志愿贡献的记账等等。

网络从八个场景之一的**现成模板**组装而成：组织者选择模板、设置参数——就得到带有自己应用程序（APK）的自己的网络。

## 这不是加密货币

- 平台**不发行也不出售代币**，不创建交易市场，也不奖励通常意义上的挖矿。
- 单位只存在于具体网络内部，某些配置下甚至完全不可转让。
- 价值在于用途（见下面的场景），而不在于单位的行情。
- 「钱包」「发行」「检查点」这些词——是已签名记录账本的技术词汇，不是金融工具的标志。

## 八个应用场景

| 序号 | 场景 | 单位 |
|------|------|------|
| 1 | 教育与机构实验室（包括模拟） | 积分或游戏货币 |
| 2 | 作为服务提供给其他应用的人性证明 | 不可转让的活动「脉搏」 |
| 3 | 共享资源的平等配额（水、网络、仓库） | 按周期的配额，不累积 |
| 4 | 志愿与街头项目（餐饮、救助） | 项目的代金券 |
| 5 | 社区的内部货币或时间银行 | 小时或货币，平均发行 |
| 6 | 志愿贡献的记账 | 已验证贡献的积分 |
| 7 | 互助资金池 | 货币，用损耗费对抗囤积 |
| 8 | 订阅资源——对循环资源的订阅（商业） | 按周期的配额，未使用的失效 |

## 网络是孤立的，这是主要属性

- 不是一张大网络，而是**许多独立的**网络。每张有自己的成员构成、自己的规则（配置）、自己的单位。
- 网络之间没有交换。一张网络的余额在另一张里毫无意义。
- 网络的规则在创建时写进**清单（manifest）**，默认不可更改；清单的哈希固定在创世包（genesis）中。如果规则不再适合社区——就启动一张新网络（这是免费的），成员自愿迁移过去。
- 网络的担保级别**从清单计算得出**，而不是自我声明：合作伙伴能看出「人」来自哪张网络、带有什么担保。
- 每张网络用**自己的应用程序**组装：应用名称中的 `Eq-<hash8>` 标签（网络标识符的短哈希）表明安装的正是你的网络；在应用内，网络以名称和标签签名——例如「cirrus · Eq-e5796f9c」。
- 在订阅网络（场景 8）中配额不累积：未使用的部分在周期边界失效，多余的可以转给需要资源的人（详见[日常操作](03-operations.md)）。

## 成员的角色

每个角色都是一个普通的钱包；没有任何人有特殊「权限」：

- **成员**——已注册的钱包；激活后获得发行并转换单位。
- **担保人**——账龄 3 个月以上的活跃成员，用自己有限的担保名额中的一个为新的人作保。
- **守护人**——预先指定的人，在手机丢失时确认恢复访问（个人守护人——2/3；或者公共守护人——3/5）。
- **提供方（provider）/ 池接收方**——在网络参数中指定的钱包（例如接受代金券的合作网点）。它不能管理网络。

## 诚实地谈谈边界

- **没有合适的智能手机就没有参与。** 协议要求带安全硬件密钥库的 Android 手机。没有变通方案（管理员代办、纸质收据）。
- **匿名不是目标。** 网络的名录在网络内部公开：成员能看到彼此的地址、状态和历史；余额可以从网络的公开状态推导出来。
- **防农场是经济性的，不是绝对的。** 创建多余钱包的代价必须高于它的收益；没有外部锚点时，技术上无法给出「一个人——一个钱包」的完全保证。
